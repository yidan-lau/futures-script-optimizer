# 测试机制说明

本目录用于验证 Skill 的五项核心能力：**原稿诊断、改写质量、案例应用、事实准确性、合规风险**。

## 一、测试目标

| 能力 | 验证什么 | 对应评分维度 |
|------|---------|-------------|
| 原稿诊断 | 能否正确识别结构缺失、Hook 薄弱、合规命中 | 诊断准确性 |
| 改写质量 | 是否补三段式、CTA、福利利益解释、口语化 | 改写质量 |
| 案例应用 | 是否引用正确规律、不把 C 类当规则 | 案例应用 |
| 事实准确性 | 是否编造产品事实/政策/投放结果 | 事实准确性 |
| 合规风险 | 是否命中红线、正确分级、正确转人工 | 合规（红线一票否决） |

## 二、测试流程

1. 从 `cases/` 取一条测试案例（含「原稿」与「预期」）。
2. 让 Skill 对原稿执行完整流程（诊断 → 合规初审 → 案例检索 → 改写 → 复审自检 → 输出）。
3. 按 `scoring-rubric.md` 对 Skill 输出逐项打分。
4. 结果写入 `results/`，文件名格式：`<案例ID>_<Skill版本>_<日期>.md`（如 `case-001_v0.1.0_20261010.md`）。
5. 记录：总分、各维度得分、命中的红线、待人工确认项、与预期的差异。

## 三、结果与版本关联

- 每个测试结果文件必须记录**被测 Skill 版本**（从 `SKILL.md` frontmatter 的 `version` 字段读取）。
- 便于追溯「某结论是哪个版本产出的」，以及版本升级后的回归对比。

## 四、合规红线的测试原则

- 合规维度采用**一票否决**：命中 `compliance-rules.md` 的 A 类「明确禁止」或 D 类「需监管沟通」却未正确转人工，则该条测试**直接判不合格**，其余维度分数作废。
- 测试案例应覆盖：命中红线、未命中禁词但语义违规、占位符掩盖数值、语境依赖（降本增效/有福了）、未覆盖新表达等场景。
